<objective>
Construir a fatia vertical que transforma a leitura paginada da API (Plano 01) em catálogo normalizado e persistido: schema SQLite (D-10/D-11), cálculo da regra de disponibilidade de estoque "grade >= 3 tamanhos" (D-04/DATA-01), infraestrutura de auditoria contínua de tags de tecido (DATA-03), e o orquestrador que encadeia tudo isso numa única execução transacional contra a categoria Vestidos real.

Antes de implementar a leitura de tags de tecido, este plano resolve a Open Question A4 do RESEARCH.md (risco médio-alto, não confirmada): se o tipo de tecido vive no campo nativo `product.tags` ou em um Metafield customizado — via checkpoint humano com inspeção real de um produto Vestidos, não suposição.

Purpose: sem persistência real + regra de negócio D-04 corretamente isolada (não inline), a Fase 3 (motor de recomendação) não teria uma fonte de verdade confiável para consumir; sem confirmar onde a tag de tecido mora, a implementação de fabric-taxonomy.js arriscaria ler o campo errado silenciosamente.
Output: SQLite populado com o catálogo real da categoria Vestidos, schema completo, e infraestrutura de auditoria de tags pronta para ser alimentada quando o usuário popular a planilha (D-07).
</objective>
