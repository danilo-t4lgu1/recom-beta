Fluxo OAuth completo (fallback se token permanente do admin não estiver disponível):
```
POST https://www.tiendanube.com/apps/authorize/token
Content-Type: application/json
Body: { "client_id": "...", "client_secret": "...", "grant_type": "authorization_code", "code": "..." }
# Resposta: { "access_token": "...", "token_type": "bearer", "user_id": 123, "scope": "write_scripts,..." }
```

Criação de Metafield (WRTE-01):
```
POST https://api.tiendanube.com/v1/{store_id}/metafields
Authorization: Bearer {access_token}
Content-Type: application/json
User-Agent: {app_name} ({contact_email})
Body: {
  "namespace": "recomendados",
  "key": "produto_sugerido",
  "value": "{product_id do produto recomendado}",
  "owner_resource": "product",
  "owner_id": {product_id do produto de teste},
  "description": "ID do produto recomendado - spike de viabilidade Fase 1"
}
```

Leitura de volta (round-trip):
```
GET https://api.tiendanube.com/v1/{store_id}/metafields/products?owner_id={product_id}&namespace=recomendados
Authorization: Bearer {access_token}
```

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Backend local ↔ API pública Nuvemshop | Chamadas autenticadas via Bearer token, saindo da máquina de desenvolvimento/execução até `api.tiendanube.com` |
| Repositório git ↔ Segredos do App Partners | `.env` contém client_secret e access_token — nunca deve cruzar essa fronteira para o histórico do git |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-01 | Information Disclosure | `app-partners-recomendados/.env` | mitigate | `.gitignore` inclui `.env`; verificado via `git check-ignore` na Task 1; nunca repetir o padrão de risco já presente em `app sob medida.txt` na raiz |
| T-1-02 | Tampering | Requisição OAuth (`POST .../apps/authorize/token`) | mitigate | Credenciais enviadas no corpo JSON do POST, nunca em query string/URL, per RESEARCH.md Don't Hand-Roll (evita vazamento em logs de acesso) |
| T-1-03 | Information Disclosure | Mensagens de erro do client wrapper | accept | Erros incluem status code e corpo da resposta para depuração local; risco baixo pois o script roda apenas localmente nesta fase, nunca exposto publicamente |
| T-1-04 | Tampering | Escrita de Metafield sem validação de `owner_id` | mitigate | `createMetafield` recebe `ownerId` explicitamente do argumento de linha de comando controlado pelo operador humano, nunca de input não confiável; V5 Input Validation (ASVS L1) satisfeito pela natureza controlada do script de spike |

</threat_model>
