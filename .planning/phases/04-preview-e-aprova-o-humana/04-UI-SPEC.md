# Phase 4 — UI Design Contract

> Visual and interaction contract for the human review/approval panel (APRV-01 to APRV-04). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — tech stack for this phase is `node:http` native (server-rendered HTML via template strings) + `better-sqlite3`, confirmed by 04-RESEARCH.md `## Standard Stack`. Not React/Next.js/Vite, so the shadcn gate does not apply. |
| Preset | not applicable |
| Component library | none — plain HTML forms/tables rendered server-side, no client framework (per Architecture Patterns: "nenhuma SPA necessária para um painel interno de baixo volume") |
| Icon library | none — use plain Unicode glyphs (`+` for added, `–` for removed) and text badges instead of an icon dependency, consistent with the zero-new-dependency constraint in 04-RESEARCH.md |
| Font | system font stack: `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif` — no web font loading, zero network dependency, appropriate for a `127.0.0.1`-only internal ops tool (Assumption A1) |

**Why no design system tooling:** this phase's UI is a single-operator internal panel served by a new, separate `node:http` process (`src/review-server.js`), rendering plain HTML with `<style>` embedded or a single static CSS file served alongside. No JS bundler, no npm package for UI exists in `app-partners-recomendados/package.json` today, and 04-RESEARCH.md explicitly recommends against introducing one ("Express adicionaria a primeira dependência de framework web do projeto... o custo de manutenção de uma dependência nova não se paga").

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between a badge and its icon glyph, gap between stacked metadata lines (cor/tecido/estoque) |
| sm | 8px | Gap between action buttons in a row, padding inside badges |
| md | 16px | Default padding inside a recommendation card, gap between cards in a grid |
| lg | 24px | Padding inside the page container, gap between the "Antes" and "Depois" columns |
| xl | 32px | Gap between the page header and the queue/diff content |
| 2xl | 48px | Vertical gap above/below the empty-state message block |
| 3xl | 64px | Not used this phase (no page is tall enough to need it) |

Exceptions: none — this is a desktop-only internal tool (operator at a workstation), so no 44px touch-target exception is needed.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 600 (semibold) | 1.2 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.2 |

- **Body (16/400/1.5):** product metadata lines (cor, tecido, estoque), empty-state body copy, error message copy.
- **Label (14/600/1.2):** badges ("Adicionado", "Removido", "Mantido"), form button text, table column headers, dry-run banner text.
- **Heading (20/600/1.2):** product name at the top of a diff card, section titles ("Antes", "Depois") on the product review page.
- **Display (28/600/1.2):** page-level titles only — "Fila de Revisão" (queue page), "Revisão: {nome do produto}" (product review page).

Exactly 4 sizes, exactly 2 weights, per contract.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Page background for both the queue page and the product review page |
| Secondary (30%) | `#F5F5F5` | Card backgrounds (recommendation cards, "Mantido"/unchanged state), page header bar, table row stripe |
| Accent (10%) | `#2563EB` | Reserved for exactly: (1) "Aprovar recomendações" primary button background, (2) "Adicionado" badge text/border + card left-border for recommendations present in "depois" but not in "antes", (3) the "Revisar" link in the queue list that opens a product's diff page, (4) `:focus` outline on all interactive elements |
| Destructive | `#DC2626` | Reserved for exactly: (1) "Remover" button (remove a single recommendation before approving, D-19), (2) "Rejeitar produto" button, (3) "Removido" badge text/border + card left-border for recommendations present in "antes" but not in "depois" |

Accent reserved for: "Aprovar recomendações" button, "Adicionado" badge/left-border, "Revisar" link in the queue table, focus rings. Never used for plain body text or as a default card border.

Destructive reserved for: "Remover" button, "Rejeitar produto" button, "Removido" badge/left-border. Never used for informational or neutral UI.

**Third diff state ("Mantido" — id present in both antes and depois):** no color emphasis — default `#F5F5F5` card background, no badge color, plain "Mantido" label in gray text (`#6B7280`). This keeps the palette at exactly 60/30/10 + one semantic (destructive) color, with accent doing double duty as the "positive/added" signal — no fifth color is introduced.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (product review page) | "Aprovar recomendações" |
| Secondary action (product review page) | "Rejeitar produto" |
| Item-level action (per card, pre-approval) | "Remover" |
| Page title — queue | "Fila de Revisão" |
| Page title — product review | "Revisão: {nome do produto}" |
| Column headers — diff | "Antes" / "Depois" |
| Diff badges | "Adicionado" (accent) / "Removido" (destructive) / "Mantido" (neutral) |
| Dry-run mode banner (shown whenever `dryRun !== false`) | "Modo simulação ativo — nenhuma escrita real será feita na loja." |
| Empty state heading (queue page, 0 produtos com mudança) | "Nada para revisar agora" |
| Empty state body | "Nenhum produto tem uma proposta de recomendação diferente do estado atual. Isso é esperado enquanto as tags de tecido do catálogo ainda não foram preenchidas — volte depois da próxima ingestão." |
| Error state (ex.: aprovação recusada pelo backend) | "Não foi possível aprovar: um ou mais itens selecionados não fazem parte da lista calculada pelo motor para este produto. Recarregue a página e tente de novo." |
| Error state (ex.: escrita sem aprovação, resposta 409 se exposta na UI) | "Este produto ainda não tem aprovação registrada. Revise e aprove antes de tentar novamente." |
| Destructive confirmation — "Remover" | Nenhum diálogo de confirmação: ação de baixo risco e não persistida até o "Aprovar" final (recarregar a página desfaz). Clique único aplica a remoção na visualização da sessão. |
| Destructive confirmation — "Rejeitar produto" | Confirmação nativa do navegador (`confirm()`, progressive enhancement — se JS estiver desabilitado, o POST segue direto): "Rejeitar as recomendações deste produto? Isso marca o produto como revisado sem aprovar nenhuma recomendação." |
