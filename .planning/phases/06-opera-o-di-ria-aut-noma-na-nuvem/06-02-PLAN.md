## Phase Goal

O sistema roda inteiramente na nuvem, todos os dias, sem depender de nenhuma máquina pessoal ligada: recalcula recomendações com base em estoque e disponibilidade atualizados, gera um novo ciclo de preview/aprovação de forma idempotente, e o Script no storefront exibe as recomendações mais recentes de forma performática (com cache local) para quem visita a loja.

*(Goal do ROADMAP mantido verbatim; não está no formato user-story canônico do modo MVP — mesma discrepância já registrada e aceita nas Fases 3/03.1/4/5 deste projeto, não bloqueia execução. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions (ambiente de execução do workflow) → secrets do repositório | Token/credenciais injetados via `${{ secrets.* }}` em tempo de execução, nunca hardcoded no YAML |
| Commit-back (`git push`) → branch `master` remota | Escrita automatizada no histórico do repositório por um bot (`github-actions[bot]`), sem revisão humana por commit individual |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-05 | Information Disclosure | `daily-recompute.yml` (bloco `env:` de secrets) | mitigate | Secrets referenciados exclusivamente via `${{ secrets.NOME }}` no bloco `env:` do step — nunca ecoados em `run:`/echo/console.log; o GitHub mascara automaticamente qualquer valor de secret que apareça em log |
| T-06-06 | Elevation of Privilege | bloco `permissions:` do workflow | mitigate | `permissions: contents: write` explícito e mínimo no nível do job — nunca `write-all` nem omitido (o que herdaria o default, potencialmente mais amplo) |
| T-06-07 | Denial of Service (auto-infligido) | commit-back disparando o próprio workflow de novo | mitigate | Mensagem de commit inclui a tag de skip de CI (Pitfall 4 do 06-RESEARCH.md) |
| T-06-08 | Tampering (falha de push mascarada) | step de commit-back | mitigate | Nenhum step usa supressão de falha (`continue-on-error`) — uma falha real de `git push` (ex: conflito, branch protection) derruba o job visivelmente (D-46), nunca mascarada |
| T-06-SC | Tampering (supply chain) | `actions/checkout`, `actions/setup-node` | accept | Actions oficiais do GitHub (marketplace verificado, mantidas pelo próprio GitHub), fixadas por major version tag — mesmo nível de confiança já aplicado a dependências existentes do projeto |
</threat_model>
