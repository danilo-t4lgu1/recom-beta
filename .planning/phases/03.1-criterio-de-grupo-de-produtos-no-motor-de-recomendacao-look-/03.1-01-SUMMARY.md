# Phase 03.1 Plan 1: Critério de Grupo de Produtos — Resolução de Grupo Summary

**Módulo puro `product-group.js` que resolve categoria Nuvemshop → grupo canônico (Look Inteiro/Partes de Cima/Partes de Baixo, D-26) por igualdade exata normalizada, expõe o par de mescla (D-27/D-28), extrai `categories[]` do shape real da API com segurança, e audita categoria não mapeada de forma sempre visível (Pitfall 3), 11/11 testes vitest verdes, zero I/O.**

## Accomplishments

- `resolveProductGroup(categoryRaw)` implementado: as 11 categorias conhecidas Nuvemshop resolvem para o grupo canônico correto (D-26) via `Map.get` após `trim().toLowerCase()`; qualquer categoria fora do mapa fechado retorna `null` explícito, nunca lança, nunca assume grupo default (T-03.1-02)
- `crossGroupOf(group)` implementado: `Partes de Cima <-> Partes de Baixo` (D-28); `Look Inteiro`, `null` e valores desconhecidos retornam `null` (D-27, auto-contido)
- `extractCategoryRaw(product)` implementado: navega `product?.categories` → `categories[0]?.name?.pt` com guarda de nulidade em cada nível, retorna `.trim()` do valor ou `null` em qualquer ponto de falha (shape ausente/vazio/malformado), nunca lança
- `auditProductGroups(products)` implementado: mesmo formato `{ frequency, unmapped }` de `auditFabricTags`, mas checando `resolveProductGroup(categoryRaw) == null` para popular `unmapped` — torna categoria não mapeada sempre visível (Pitfall 3), nunca silenciosa; produtos sem categoria extraível são pulados sem erro
- Normalização confirmada por teste: `resolveProductGroup(' BLUSAS ')` e `resolveProductGroup('Blusas')` retornam o mesmo valor (`GROUP_PARTES_DE_CIMA`)
- Verificado por grep: resolução usa `Map.get`, nunca `.includes()` (nunca substring/fuzzy, ao contrário do resolver de tecido D-32)
- 11 comportamentos cobertos em vitest; suite completa do projeto (5 arquivos, 43 testes) permanece verde — nenhuma regressão
