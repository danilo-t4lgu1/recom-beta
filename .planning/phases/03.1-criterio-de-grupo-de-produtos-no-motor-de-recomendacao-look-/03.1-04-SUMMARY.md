# Phase 03.1 Plan 04: Ingestão — Extração de Grupo e Correção Multi-Categoria (D-33) Summary

**`ingest-catalog.js` agora extrai `categoryRaw`/`productGroupCanonical` de `product.categories[]` (sem chamada de rede nova) e `runIngestion({ categoryNames })` mescla múltiplas categorias sob um único `run_id`, corrigindo o Pitfall 1/D-33 — comprovado por `getLatestSnapshotProducts()` real contra banco SQLite temporário, 5/5 testes novos verdes, 64/64 na suíte completa.**

## Performance

- **Duration:** ~25 min
- **Tasks:** 2
- **Files modified:** 3 (1 criado, 2 modificados)

## Accomplishments

- `ingest-catalog.js` importa `resolveProductGroup`/`extractCategoryRaw`/`auditProductGroups` de `product-group.js` (Plano 03.1-01); loop de produtos extrai `categoryRaw`/resolve `productGroupCanonical` ao lado do bloco já existente de tecido, persistindo ambos em `catalog_snapshots` via `persistIngestionBatch`
- `runIngestion` estendido para `{ categoryName = 'Vestidos', categoryNames }`: `categoryNames`, quando presente e não-vazio, tem prioridade; cada nome é resolvido via `resolveCategoryIdByName` (loop sequencial), os produtos de cada categoria resolvida são mesclados em um único array com dedup por `String(product.id)` via `Map` (T-03.1-04), e uma ÚNICA `ingestion_run` é aberta para todas as categorias combinadas (`categoryId`/`categoryName` unidos por vírgula) — corrige o Pitfall 1/D-33: `getLatestSnapshotProducts()` agora retorna produtos de TODAS as categorias ingeridas juntas, mesmo quando ingeridas em uma única chamada com múltiplos nomes
- Categoria de produto não mapeada (Pitfall 3) nunca lança: `auditProductGroups` audita o lote mesclado uma vez, `console.warn` é emitido por categoria distinta não mapeada citando explicitamente que produtos dessa categoria ficam sem grupo (fora do motor); `unmappedCategoryCount` adicionado ao retorno de `runIngestion`, ao lado de `unmappedTagCount` já existente
- Retrocompatibilidade confirmada: `runIngestion({ categoryName: 'Vestidos' })` (chamada antiga, sem `categoryNames`) continua funcionando exatamente como antes
- `src/ingestion/ingest-catalog.test.js` criado (primeiro teste automatizado deste arquivo): client Nuvemshop (`listCategories`/`listProducts`/`getMetafields`) inteiramente mockado via `vi.mock`, isolado de rede real; `CATALOG_DB_DIR` + `vi.resetModules()` + import dinâmico isolam cada teste em SQLite temporário próprio, nunca tocando `data/catalog.db` real — 5 comportamentos cobertos (extração/persistência de grupo single-categoria, correção D-33 com `getLatestSnapshotProducts()` real, categoria não mapeada com spy em `console.warn`, retrocompatibilidade, dedup de produto duplicado entre categorias mescladas)
- `scripts/run-ingestion.js` atualizado: `process.argv.slice(2)` vira `categoryNames` (default `['Vestidos']` se nenhum argumento for passado — ex.: `node scripts/run-ingestion.js Blusas Calças`), chama `runIngestion({ categoryNames })`, resumo final agora inclui `unmappedCategoryCount`

## Decisions Made

- `categoryNames` tem prioridade sobre `categoryName` apenas quando é array não-vazio — mantém a assinatura antiga funcionando sem nenhuma mudança de comportamento para chamadas existentes (Test 4)

- `ingestion_runs.category_id`/`category_name` viram strings unidas por vírgula para múltiplas categorias combinadas — evita qualquer mudança de schema na tabela `ingestion_runs`
