<decisions_made>

- **Dois projetos Vercel separados** (`app-partners-recomendados` público +
  `recom-admin` novo) em vez de reaproveitar o mesmo projeto: o endpoint
  `/api/recommendations/:id` é consumido AO VIVO pelo navegador de clientes anônimos no
  storefront (`talgui.com.br`) — não pode exigir login. Ligar proteção no projeto
  existente quebraria o carrossel de recomendados em produção. Confirmado por teste
  real: `curl https://app-partners-recomendados.vercel.app/api/recommendations/349886153`
  → 200 seguiu funcionando durante toda a sessão.
- **Vendorização de arquivos dentro de `web/`** (`web/api/_lib/*.js`, `web/api/_data/catalog.db`,
  gerados por `web/scripts/prepare-admin-api.mjs`, COMMITADOS no git — não gerados no
  build da Vercel): a Vercel não expõe arquivos fora da Root Directory durante o build,
  então `web/api/dashboard.js` não conseguia importar `../../src/db/catalog-store.js`
  nem ler `../../data/catalog.db` direto. Rodar `npm run sync:admin-api` (dentro de
  `web/`) e commitar é OBRIGATÓRIO sempre que `catalog-store.js`/`schema.sql`/
  `admin-dashboard.js` mudarem de conteúdo — isso NÃO é automático (só o catalog.db é,
  via o workflow diário). Risco real de drift se alguém editar `catalog-store.js` sem
  lembrar de re-sincronizar.
- **Basic Auth via Edge Middleware em vez do toggle nativo "Vercel Authentication"**:
  a opção que protege TODOS os deployments (incluindo os aliases `.vercel.app`
  "bonitos", não só URLs de deploy com hash) é **Pro-only**. No plano Hobby (o do
  usuário), o toggle gratuito só protege URLs de deployment com hash — os aliases
  ficavam públicos mesmo com a proteção "ligada". Implementei `middleware.js`
  (HTTP Basic Auth, credenciais em Environment Variables) como alternativa gratuita
  que cobre 100% das URLs do projeto, em ambos os painéis.
- **catalog.db real cresce ~16MB e sobe todo dia** (snapshot append-only,
  `catalog_snapshots`) — cópia vendorizada em `web/api/_data/catalog.db` cresce junto.
  Sem problema agora (bem abaixo do limite de tamanho de função da Vercel), mas é um
  crescimento sem teto — não é escopo desta sessão resolver, só registrar.
</decisions_made>
