# Plan 11.2: Vercel Serverless Endpoints & API Client

## Objective
Criar os novos endpoints HTTP Serverless em `web/api/` e o cliente unificado frontend em `web/src/api/client.js` seguindo as melhores práticas do `/backend-architect` (validação defensiva de inputs, status codes corretos, headers de cache control e tratamento de erro desacoplado).

  <files>web/api/products-search.js, web/api/recommendations-inspect.js, web/api/co-purchase-pairs.js, web/api/catalog-health.js</files>
  <action>
    Implementar os handlers serverless seguindo o padrão de isolamento em `/tmp/recom-admin-db` já estabelecido em `web/api/dashboard.js`:
    1. `web/api/products-search.js`: Rota `GET` que recebe `?q=...` e `?limit=...`, valida parâmetros e chama `searchCatalogProducts`.
    2. `web/api/recommendations-inspect.js`: Rota `GET` que recebe `?productId=...`, valida obrigatoriedade do ID e retorna a vitrine inspecionada via `inspectProductRecommendations`.
    3. `web/api/co-purchase-pairs.js`: Rota `GET` que recebe `?page=...&limit=...&category=...&onlyInStock=...&sortBy=...`, conecta a `selectAllCoPurchasePairsStmt` e chama `getCoPurchasePairsReport`.
    4. `web/api/catalog-health.js`: Rota `GET` consolidando a saúde do catálogo, cobertura das 11 categorias e margem do disjuntor de segurança.
    USE: HTTP 400 para parâmetros inválidos, HTTP 404 para produto não encontrado, HTTP 405 para métodos não-GET e HTTP 500 com log para falhas inesperadas.
  </action>
